# 登录校验与操作日志

## 请求经过的顺序

1. `LoginController` 接收 `POST /login`，账号密码验证通过后由 `JwtUtils` 签发 JWT。
2. 前端将 `data` 保存为 `loginUser`，后续请求通过 `token` 请求头发送 JWT。
3. `TokenFilter` 校验签名、有效期和员工 ID；失败返回 HTTP 401，由现有前端跳转登录页。
4. 校验通过后，把员工 ID 保存到 `CurrentHolder`，放行进入 Controller。
5. 标注 `@Log` 的写操作进入 `OperationLogAspect`：先保存脱敏入参，再执行原方法，最后记录返回值及耗时。
6. 原方法正常返回才插入 `operate_log`；抛出的业务异常保持原有处理。日志落库失败会记录错误，不改变已经成功的业务返回值。
7. 请求结束时，Filter 在 `finally` 中移除 ThreadLocal 数据，避免线程复用造成操作人串号。

## 前端联调

现有 Nginx 前端已经包含登录、`token` 请求头拦截器、401 跳转和日志分页页，无需修改压缩后的前端脚本。

1. 在 IDEA 重新加载 Maven 并重启后端，默认端口 8080。
2. 启动现有 Nginx，打开 `http://localhost:90`。Nginx 将 `/api/` 请求转发到后端并去掉 `/api` 前缀。
3. 重新登录，避免浏览器仍使用旧版本返回的空 Token。
4. 新增或修改一条部门、员工、班级或学员记录；然后进入“日志管理”。
5. 确认操作人、时间、类名、方法名、入参、返回值、耗时均显示，翻页正常。

日志接口：`GET /log/page?page=1&pageSize=10`；默认第 1 页、每页 10 条，每页上限 100。返回 `data.total`、`data.rows`，关联员工表得到 `operateEmpName`；员工已删除的历史日志仍保留。

## 本地密钥

默认不需要修改数据库配置：未配置 JWT 密钥时，程序会在启动时生成临时随机密钥，所以每次重启后需要重新登录。

若希望重启后保留令牌有效性，可在 IDEA 运行配置的环境变量中设置 `TLIAS_JWT_SECRET`，内容至少 32 个 UTF-8 字节，建议使用随机字符串。也可在被 Git 忽略的本地 `application.yaml` 中配置 `tlias.jwt.secret`。不要提交真实密钥或密码。

## 日志范围和隐私

- 通过 Controller 写操作上的 `@Log` 控制记录范围，查询和登录不生成操作日志。
- 不记录登录密码、Token，嵌套对象中的密码、手机号、身份证号和地址会脱敏。
- 文件仅记录大小和类型；超长参数/返回值最多保留 1900 个字符。
- 此版只记录正常返回的写操作；若以后需要失败审计，应增加状态字段和独立的失败记录策略。
- JWT 采用签名和有效期校验，退出登录目前沿用前端删除本地令牌，不包含服务端即时吊销机制。

## 自动验证

`OperationLogIntegrationTests` 使用隔离的 H2 内存数据库和真实 HTTP 请求，验证登录、鉴权、日志插入、关联姓名、分页、失败操作、字段脱敏以及线程清理，不写入本地 MySQL 的学习数据。
